■ 2. 현재까지 완료된 핵심 작업

[데이터 진단/전처리]
- 원본 2021-01-01 ~ 2021-09-14, 6,168행(257일 x 24시간)을 기준으로 전처리 파이프라인이 구성되어 있다.
- preprocess.load()가 전체 분석/학습의 단일 진입점으로 사용된다.
- 시간 컬럼 손상일 복구, 결측 처리, 가동 중단, 휴무일, 생산기록 누락 의심일, 복제일 플래그가 구현되어 있다.
- 하루 24행 및 1시간 연속성 assert 검증이 있어 lag 생성 전 데이터 무결성을 확인한다.
- 학습용 train_ok_strict와 평가용 train_ok가 분리되어 있다.

[복제/증강 데이터 대응]
- 257일 중 161일이 동일 24시간 전력곡선을 공유하는 복제일로 탐지되어 있다.
- 분석과 평가는 복제일/고유일을 분리해 보는 방향이 확립되어 있다.
- 복제일을 완전히 제거하는 방식은 학습량 부족 때문에 좋지 않다는 실험 근거가 확보되었다.
- 생산계획을 사용하는 최종 후보에서는 복제일 가중치 0.3이 현재 가장 안정적이다.

[EDA]
- 일 최대전력, 요일x시간 패턴, 생산량/기온 관계, 분포, 상관, 복제 증거 등 7개 시각화가 생성되어 있다.
- 전력은 약 23 / 105 / 165의 기저·중·고부하 상태로 나뉘는 특성이 확인되었다.
- 평일 8~11시, 13~19시에 부하가 높고 12시에 하락하는 패턴이 확인되었다.
- 생산량은 전력과 가장 강하게 연결되고 약 800 전후부터 포화되는 형태가 확인되었다.
- 기온은 전체 상관보다 가동시간에서 의미가 크고 약 22도 이상에서 냉방성 부하 증가가 관찰되었다.

[피처 엔지니어링]
- full / no_plan / h7_full / h7_no_plan 피처 세트가 구현되어 있다.
- 달력, 생산계획, 기상, 과거 전력 lag가 예측 시점 기준으로 구분되어 있다.
- 1주 앞 예측에서는 lag24 등 아직 존재하지 않는 최근 정보가 제거되어 누수를 방지한다.
- target_max15와 target_max15_trapz 두 방식의 15분 최대 타깃이 생성되어 있다.
- 시간평균 -> 15분 최대 환산용 peak_ratio.csv가 생성된다.

[베이스라인]
- lag168, 요일x시간 평균, lag24, 전체 평균 4종이 동일 롤링 폴드 규약으로 평가된다.
- 최신 고유일 목표선:
  · MAE 23.64
  · RMSE 35.28
  · peakMAE 35.51
- 복제일에서 lag168 성능이 과도하게 좋아지는 현상이 수치로 확인되어 랜덤 분할 금지 근거가 확보되어 있다.

[모델]
- LightGBM과 RandomForest가 구현되어 있다.
- 5~9월 시간순 롤링 폴드, 시드 3개 반복, 고유일 중심 평가 구조가 구현되어 있다.
- 복제일 처리, strict 여부, 생산계획 유무, 예측 horizon, 가중치 조합을 포함한 17개 설정 비교가 완료되어 있다.

[현재 최종 후보]
1) 생산계획/기상을 사용할 수 있는 경우
   - 설정 8: h7_full + 복제일 가중치 0.3 + train_ok_strict
   - MAE 8.77 / RMSE 16.33 / peakMAE 16.52
   - 현재 전체 MAE와 RMSE 기준 가장 좋은 후보이며 시드 흔들림도 약 0.09로 작다.

2) 생산계획이 없는 경우
   - 설정 7: h7_no_plan + 복제일 그대로 + train_ok_strict

   - no_plan에서 복제일 가중치를 낮추면 오히려 성능이 악화되어 full과 다른 처리 방침이 필요하다.

[예측 파이프라인]
- forecast.py가 특정 날짜의 24시간 전력을 1주 앞 시점에서 예측할 수 있도록 구현되어 있다.
- 학습 cutoff를 대상일 7일 전으로 제한해 미래 정보 누수를 막는다.
- 시간 평균 예측과 15분 최대 환산 결과를 함께 출력한다.

[재현성]

- README에 폴더 구조와 실행 방법이 정리되어 있다.


■ 3. 현재 문서와 실제 코드 사이에서 확인된 정리 필요 사항

1) 베이스라인 숫자

- 실제 현재 run_all.py에는 model.py와 forecast.py까지 포함된 8단계가 이미 구현되어 있다.
- 해당 항목은 완료로 취급한다.

3) 단계 수 표기
- 작업내역.txt 일부에는 "현재 7단계"라는 과거 문구가 남아 있으나 실제 파이프라인은 8단계다.
- 추후 문서 정리 시 8단계로 통일해야 한다.

4) 모델 설정의 의미

- 실제 예측 후보 forecast.py는 clone='weight', CLONE_W=0.3을 사용한다.
- 실험 기준점과 최종 후보 설정을 문서에서 구분해서 표현해야 혼동이 없다.

■ 5. 발전 방향 — 권장 우선순위

[1순위] 최종 모델 튜닝보다 "오차 분석"을 먼저 완성
이유:
- 예측 성능은 이미 베이스라인을 크게 넘었다.
- 대회 배점에서 영향요인/오류분석이 15점이며 아직 미완료다.
- 오차 조건을 알아야 이후 피처 추가나 모델 개선에 근거가 생긴다.

권장 산출물:
- src/error_analysis.py
- outputs/error_predictions.csv
- outputs/error_by_condition.csv
- outputs/error_worst_cases.csv
- outputs/error_analysis/*.png

필수 분석 항목:
- abs_error, signed_error(과소/과대)
- hour / dow / month
- prod_zero / 생산량 구간 / prod_cap 구간
- temp <=22 / 22~26 / 26+
- after_off / off_run_prev
- is_transition
- 실제 피크 여부
- 모델이 가장 크게 틀린 상위 20~50개 시점


[2순위] 15분 최대를 직접 예측하는 모델 추가
현재 과제의 현장 활용은 최대수요전력과 직접 연결된다.
시간 평균만 잘 맞는 모델보다 target_max15를 직접 맞히는 모델이 대회 스토리에 더 강하다.

실험 구조:
A. 시간평균 예측 -> peak_ratio 환산
B. target_max15 직접 회귀
C. 필요하면 두 결과 앙상블

비교 지표:
- max15 MAE / RMSE
- 피크 구간 MAE
- 실제 상위 5% 피크 Recall
- 일 최대 피크 시각 오차


[3순위] SHAP + 상호작용으로 영향요인 설명 강화
보고서에서 단순 상관분석과 모델 기반 설명을 연결한다.
핵심 확인 대상:
- prod 또는 prod_cap
- lag_week_mean4 / lag168
- temp와 생산량의 상호작용
- 휴무 복귀 관련 피처
- hour / dow

주의:
생산량과 공장인원은 상관이 0.99라 SHAP 중요도가 서로 분산될 수 있다.
최종 해석 모델에서는 공장인원을 빼는 실험도 고려한다.


[4순위] 피크 저감 스케줄링 연결
예측 결과를 "그래서 무엇을 바꿀 것인가"로 연결해야 한다.

최소 구현안:
- 예측 피크 위험시간을 찾는다.
- 해당 시간의 생산량 일부를 피크가 낮은 시간대로 이동한다.
- 하루 총생산량은 유지한다.
- 야간 이동에는 인건비 계수 1.5 패널티를 적용한다.
- 이동 전/후 예측 15분 최대, 전력비용 proxy, 인건비 증가량을 비교한다.

이 단계가 현장 활용 10점 + 창의성 10점의 핵심이 될 수 있다.


[5순위] 모델 성능 마무리
구조를 확정한 뒤에만 하이퍼파라미터를 조정한다.
권장 탐색 범위는 과도하게 넓히지 않는다.
- num_leaves
- min_data_in_leaf
- learning_rate / n_estimators
- feature_fraction
- bagging_fraction
- L1/L2 regularization

검증은 현재 시간순 롤링 폴드를 그대로 유지한다.
최종 선택은 MAE 하나가 아니라 MAE / RMSE / peakMAE / 시드 흔들림을 함께 본다.


[6순위] 불확실성 추정 추가
LightGBM quantile objective로 P10/P50/P90 예측 구간을 만들 수 있다.
피크 위험시간에 예측 상한(P90)이 임계값을 넘는지 경보하는 방식으로 연결하면
"예측값 1개"보다 현장 의사결정에 유용하고 창의성 항목에도 도움이 된다.


[7순위] 제출 패키지 정리
- environment.yml 버전 고정
- README 최신화
- run_all.py 최종 smoke test
- 산출물 파일명/컬럼 설명 문서화
- 보고서 수치와 outputs/*.csv 일치 여부 최종 검사
- 개인 문서의 옛 수치/완료된 TODO를 정리하고, 공용 작업내역.txt는 최신 결정만 남긴다.

- run_all.py는 현재 전처리 -> EDA -> 통계 -> 패턴 -> 피처 -> 베이스라인 -> 모델 비교 -> 예측오차 분석 -> 예측의 9단계 구조.
- error_analysis.py는 정식 파이프라인에 포함.
- operational_correction.py는 선택 실험으로 유지.
- 신규 스크립트 py_compile 및 결과 파일 생성 확인 완료.


■ 현재 핵심 해석

- 프로젝트는 이제 "모델을 처음 만드는 단계"가 아니라 "최종 모델 후보를 검증하고 피크 예측/현장 활용으로 확장하는 단계"다.
- 일반 시간대 평균오차는 이미 베이스라인 대비 크게 개선됐다.
- 남은 핵심 과제는 최대피크 직접 예측, 피크 과소예측 보완, 영향요인 해석, 현장 적용 가능한 피크 저감안 제시다.
- 현재 가장 큰 오류 사례는 단순 생산량 부족이 아니라 공휴일 부분가동/생산 종료 후 기저부하 전환과 같은 운영 상태 변화다.
- 따라서 이후 모델 개선은 단순 하이퍼파라미터 조정보다 운영상태/피크 구조를 반영하는 방향이 우선이다.


■ 다음 작업 우선순위

[1순위] 15분 최대전력 직접 예측
- target_max15를 직접 LightGBM으로 학습.
- 기존 시간평균 예측 x peak_ratio 방식과 동일 롤링 폴드에서 비교.
- MAE/RMSE 외에 peakMAE, 피크 Recall, 일 최대전력 오차, 피크 시각 오차 평가.

[2순위] SHAP 영향요인 분석
- 최종 후보 모델 기준 전역/개별 SHAP 분석.
- prod, lag_week_mean4, lag168, hour, temp, 휴무/생산종료 관련 변수의 기여 확인.
- 예측오차가 큰 사례와 SHAP 결과를 연결해 보고서 근거로 사용.

[3순위] 피크 과소예측 개선
- peak-weighted LightGBM.
- Quantile LightGBM(P50/P90) 기반 불확실성 추정.
- 필요 시 피크 분류 + 전력 회귀 2단계 모델 비교.

[4순위] 운영규칙 보정 재검증
- 9월 홀드아웃 또는 별도 테스트 구간에서 production-end 보정 효과 확인.
- 재현되면 제조 운영 규칙을 결합한 하이브리드 모델로 최종 후보에 편입.

[5순위] 현장 활용/피크 저감
- 예측 피크 시간의 생산량 일부를 비피크 시간대로 이동하는 스케줄링 설계.
- 하루 총생산량 유지 + 최대수요전력 최소화 + 야간 인건비 가중치 반영.
- 예측 -> 위험시간 탐지 -> 일정 조정 -> 예상 피크 감소량 흐름으로 연결.

[6순위] 최종 재현성 정리
- environment.yml 버전 고정.
- 전체 run_all.py 재실행 검증.
- README / 결과파일 / 작업내역 동기화.
- 최종 제출용 예측결과 파일 및 보고서용 수치 확정.
