==============================================================
 Resource optimization AI.py  사용법
 KAMP 과제 ⑤ 제조 생산데이터 기반 전력사용량 예측 및 최대피크 위험조건 분석
 작성 2026-10-05 (조선제)
==============================================================

 이 파일 하나만 돌리면 전처리부터 저감방안까지 전부 진행되고,
 결과가 콘솔에 찍히면서 대시보드(브라우저로 보는 화면)가 다시 만들어진다.

 한 줄 요약
   conda activate kamp-contest
   python "Resource optimization AI.py" --serve

 --serve 를 붙이면 돌린 뒤 브라우저가 자동으로 열린다. 이게 제일 편하다.


==============================================================
 1. 처음 한 번만 — 환경 만들기
==============================================================

 저장소를 받은 폴더에서 (예: C:\Users\내이름\kamp-contest\kamp-contest)
 environment.yml 이 그 폴더에 있으므로 환경을 만들 때는 거기서 해야 한다.

   conda env create -f environment.yml
   conda activate kamp-contest

 이미 환경이 있으면 activate 만 하면 된다. 프롬프트 앞에 (kamp-contest) 가
 떠 있어야 한다. (base) 로 떠 있으면 아직 활성화가 안 된 것이다.

 이 파일이 쓰는 패키지는 네 개뿐이다
   numpy · pandas · lightgbm · scikit-learn
 matplotlib·shap 은 필요 없다 (그건 src/ 의 그림 코드가 쓴다).

 ※ environment.yml 에 버전이 고정돼 있다. 버전이 다르면 MAE 가 소수점에서
   달라져 4번의 검증 블록이 "★ 다름" 을 띄우기 때문이다.
     numpy 2.4.6 · pandas 3.0.6 · scikit-learn 1.9.1 · lightgbm 4.7.0

 ※ BLAS 가 openblas 로 못박혀 있다 (libblas=*=*openblas).
   이게 없으면 MKL 이 깔리는데, 그러면 numpy 행렬곱에서 파이썬이 오류 메시지도
   없이 그냥 죽는다. 증상이 나는 곳과 원인이 있는 곳이 달라 찾기 어려운 문제다.
   의심되면 한 줄로 확인된다:
     python -c "import numpy as np; print(np.eye(2) @ np.eye(2))"
   이게 죽으면 BLAS 문제다.  conda install -c conda-forge "libblas=*=*openblas"

 ※ environment.yml 은 영어 주석만 쓴다. 윈도우에서 conda 가 이 파일을 cp949 로
   읽어서 한글 주석이 있으면 디코딩 오류를 낸다. 한글 설명은 이 사용법 파일에 둔다.

 데이터는 저장소에 들어 있다 → dataset/okm_augumented_2021.csv
 따로 받을 필요 없다.


==============================================================
 2. 돌리기
==============================================================

   python "Resource optimization AI.py"              돌리고 결과만 본다
   python "Resource optimization AI.py" --serve      돌린 뒤 브라우저로 띄운다
   python "Resource optimization AI.py" --serve-only 안 돌리고 띄우기만 (바로)
   python "Resource optimization AI.py" --serve --port 8080   포트 바꾸기

 ★ 따옴표를 꼭 붙일 것. 파일 이름에 공백이 있어서 따옴표가 없으면
   PowerShell 이 "Resource" "optimization" "AI.py" 세 개로 읽고 실패한다.

 --serve 는 http://127.0.0.1:8000 으로 띄운다. 끝내려면 그 창에서 Ctrl+C.
 이 컴퓨터 안에서만 열린다 — 다른 사람은 접속할 수 없다.
 포트가 이미 사용 중이면 8001, 8002 … 로 자동으로 옮겨 간다.

 약 4분 걸린다. 중간에 "완료" 가 하나씩 찍히니 멈춘 게 아니다.
 끝나면 종료 코드가 0 이면 정상, 1 이면 검증에서 어긋난 항목이 있다는 뜻이다
 (4번 항목 참고).


==============================================================
 3. 콘솔에 찍히는 것 — 9단계
==============================================================

 [1] 전처리
     원자료 6,168행 / 257일을 읽어 정리한다.
     복제일(전력곡선이 통째로 같은 날) 161일, 휴무일 49일,
     기록손상 2일, 생산기록 누락 의심 15일을 가려낸다.
     학습에 쓸 수 있는 행 5,788개가 여기서 정해진다.

 [2] 피처 생성
     1주 앞 예측용 34개 / 하루 앞용 36개.
     결측이 있는 피처와 그 비율도 같이 찍는다.

 [3] 모델 성능
     설정 6개를 같은 기준에서 비교한다. 표를 그대로 보고서에 쓸 수 있다.
     "흔들림" 은 시드 3개의 표준편차다. 설정 간 차이가 흔들림보다 작으면
     차이가 없다고 본다 — 이게 이 과제에서 제일 자주 쓰는 판단 기준이다.
     아래에 월별 오차도 나온다. 5월은 학습이 4개월뿐이라 따로 본다.

 [4] 최대피크 예측
     · 일 최대를 분위 0.9 로 추정한 것과 점 예측의 최대를 비교한다.
       점 예측은 시각마다 가운데 값을 맞히므로 그 24개의 최대는 구조적으로 낮다.
     · 피크 "시각" 은 맞힐 수 없다는 수치도 같이 나온다
       (모델 적중률 vs "무조건 8시" 규칙).
     · 15분 최대(요금이 매겨지는 기준)를 직접 학습한 것과 계수로 환산한 것 비교.

 [5] 최대피크 위험조건
     기온 x 생산 교차표. 이 과제의 핵심 결과다.
     생산이 하위 1/3 이면 기온이 30도를 넘어도 피크일이 0% 다.
     생산이 중위 이상일 때만 기온이 비율을 올린다 →
     생산은 필요조건, 기온은 그 위에서 위험을 올리는 증폭 요인.

 [6] 피크 위험 경보
     · 1주 전(D-7) 과 하루 전(D-1) 이 거의 같다 → 미리 내도 성능을 안 잃는다.
     · 15분 최대 기준이 정밀도가 가장 높다.
     · 임계값 스윕 — 피크 정의(D10)가 정해지면 이 표에서 값만 고르면 된다.
       "경보율" 을 꼭 같이 볼 것. 정밀도·재현율이 100% 라도 경보율이 60% 면
       이틀에 한 번 경보가 나가 현장이 무시한다.

 [7] 피크전력 저감방안
     모델을 쓰지 않고 실측만으로 낸다.
     · 시각별 전력 상승폭 → 설비가 한꺼번에 켜지는 시각을 특정한다
       (아침 8시, 그리고 12시에 세웠다가 13시에 재기동).
     · 월 최대를 만든 날의 봉우리와 2위의 간격 = 기동 분산으로 얻을 수 있는 양.
     · 일생산 구간별 일 최대 → 생산을 옮기는 것으로는 효과가 작다(포화).

 [8] 검증   ← 아래 4번에서 자세히
 [9] 대시보드 재생성

 ★ 다름 이 뜨는 경우 두 가지

       · LightGBM 버전이 다르면 소수점이 조금 달라질 수 있다.
         확인:  python -c "import lightgbm;print(lightgbm.__version__)"
         작성 시점 기준  lightgbm 4.7.0 / scikit-learn 1.9.1 /
                        pandas 3.0.6 / numpy 2.4.6
       · src/ 쪽만 고치고 이 파일을 안 고쳤거나 그 반대일 수 있다.
         그때는 조선제에게 알려 줄 것.


==============================================================
 5. 대시보드 보기 — 두 가지 방법
==============================================================

 (가) 로컬 서버로  ← 값을 자주 바꿔 볼 때 편하다
   python "Resource optimization AI.py" --serve        돌린 뒤 띄운다
   python "Resource optimization AI.py" --serve-only   이미 돌려 둔 값을 띄운다

   브라우저가 자동으로 열린다 (http://127.0.0.1:8000).
   이 방식은 화면이 옆에 있는 dashboard_data.json 을 직접 읽는다. 그래서
   파이썬을 다시 돌린 뒤에는 브라우저 새로고침(F5)만 하면 값이 바뀐다.
   끝내려면 실행한 창에서 Ctrl+C.

 (나) 파일을 그냥 열기  ← 남에게 보내 줄 때
   ii outputs\final\dashboard.html
   (ii 는 Invoke-Item 의 줄임말. 기본 브라우저로 열린다)
   VS Code 안에서 보려면  code outputs\final\dashboard.html

   이때는 브라우저가 보안상 옆 파일 읽기를 막기 때문에, 페이지 안에 박아 둔
   값을 쓴다. 값은 (가) 와 똑같다 — 파이썬이 돌 때 둘 다 갱신하기 때문이다.
   서버가 필요 없으니 이 html 파일 하나만 카톡으로 보내도 그대로 열린다.

 ★ 화면 맨 위에 "2026-10-05 21:20 실행분 · 로컬 서버에서 읽음" 처럼
   값이 언제 나온 것이고 어디서 읽었는지가 찍힌다. 옛 화면을 새 값으로
   착각하지 않도록 넣어 둔 것이다.

 구성 — 왼쪽 레일로 이동한다
   00 요약        핵심 지표 4개
   01 모델 성능    목표선 대비 · 월별 · 최종 설정
   02 최대피크 예측 일 최대 산점도 · 피크 시각 분포 · 15분 최대
   03 위험조건     기온 x 생산 교차표 · 조건별 피크일 비율
   04 경보        예측 시계 · 임계값 스윕
   05 저감방안     3축 판정 · 기동 램프 · 월 최대일 기회
   06 한계        보고서에 같이 적어야 할 것

 막대나 점에 마우스를 올리면 값이 뜬다.

 ★ 인터넷은 어느 방식이든 필요 없다. 없으면 글꼴만 기본 글꼴로 바뀌고
   내용은 똑같다. (나) 방식은 서버도 필요 없어서 html 파일 하나만 복사해 줘도
   그대로 열린다.

 7. 자주 나는 오류
==============================================================

 "Python" 만 찍히고 아무 일도 안 일어난다
   → conda 환경이 활성화 안 됐다. Windows 가 Microsoft Store 설치용
     가짜 python 을 실행한 것이다.
     conda activate kamp-contest  를 먼저 할 것.
     그래도 안 되면 전체 경로로:
     & "C:\Users\내이름\anaconda3\envs\kamp-contest\python.exe" "Resource optimization AI.py"

 ModuleNotFoundError: No module named 'lightgbm'
   → 환경이 다르거나 안 만들어졌다. 1번으로 돌아갈 것.

 can't open file '...\Resource'
   → 따옴표를 안 붙였다. python "Resource optimization AI.py"

 원자료가 없다: ...\dataset\okm_augumented_2021.csv
   → dataset 폴더가 실제로 없는 것이다. git pull 로 저장소를 다시 받을 것.
     ※ 어느 폴더에서 실행하든 상관없다. 이 스크립트는 자기가 있는 위치를 기준으로
       dataset 과 outputs 를 찾는다. 바탕화면에서 전체 경로로 실행해도 된다.
       다만 결과 파일은 스크립트가 있는 폴더의 outputs/ 에 쌓인다.

 한글이 깨져 보인다
   → 보통은 안 깨진다. 깨지면 한 번만:
     $env:PYTHONIOENCODING="utf-8"

 AssertionError: 하루 24행이 아닌 날
   → 데이터가 깨졌다. 그 날짜가 같이 찍히니 원자료를 확인할 것.

 --serve 로 띄웠는데 브라우저가 안 열린다
   → 콘솔에 찍힌 주소를 직접 복사해 브라우저에 붙여 넣으면 된다.
     기본값은 http://127.0.0.1:8000/dashboard.html
     포트가 쓰이고 있으면 8001, 8002 … 로 옮겨 가니 콘솔에 찍힌 번호를 볼 것.

 --serve-only 했더니 "대시보드가 아직 없다" 가 나온다
   → 한 번도 안 돌린 것이다. --serve-only 를 빼고 먼저 한 번 돌릴 것.

 서버로 띄웠더니 값이 옛날 것이다
   → 브라우저 새로고침(F5). 그래도 그대로면 Ctrl+F5 (강제 새로고침).
     화면 맨 위의 "… 실행분" 날짜를 보면 언제 값인지 바로 알 수 있다.

 Ctrl+C 를 눌러도 서버가 안 꺼진다
   → 창을 닫으면 같이 꺼진다. 그래도 포트가 잡혀 있으면 --port 로 다른 번호를
     쓰면 된다.


==============================================================
 8. src/ 폴더와의 관계
==============================================================

 이 파일은 "한 번에 돌려서 결과를 본다" 용 실행본이다.
 src/ 아래 모듈들이 작업용 원본이고, 지우면 안 된다.

   python "Resource optimization AI.py"   약 4분. 수치 + 대시보드
   python run_all.py                      약 12분. 18단계. 그림·CSV 까지 전부
   python src/model.py --fix              약점 공략 실험 30개
   python src/reinforce.py                강화 실험 (수단을 재고 기각한 기록)
   python src/peak_schedule.py --validate 저감 제안을 쓸 수 있는지 재는 관문

 왜 값이 왜 그런지, 무엇을 시도하고 무엇을 기각했는지는
 작업내역(조선제).txt 에 전부 적혀 있다. 그 문서 맨 위에
 "어느 파일을 보면 무엇을 알 수 있나" 목록이 있다.


==============================================================
 9. 알고 쓸 것 (보고서에도 들어가야 하는 한계)
==============================================================

 · 테스트 구간이 8일을 넘으면 뒤쪽 날의 정확도가 떨어진다.
   8일째부터 lag168(1주 전)이 테스트 구간 안을 가리켜 값이 없기 때문이다.
