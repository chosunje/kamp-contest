# 최종 모델과 피크 저감 일정 시연

날짜별 전력 예측을 현장에서 검토할 수 있는 작업 일정 추천으로 연결했다. 기존 모델 비교·D07·D10의 실험 파일을 보존하고, 운영 입력을 제한한 예측 묶음과 제약 기반 일정 추천, 로컬 HTML 화면을 추가했다.

## 실행

```bash
python run_dashboard.py --open
```

`http://127.0.0.1:8765`에서 사용한다. 다른 프로세스가 포트를 사용하면 `--port 8766`을 지정한다. 종료는 터미널에서 Ctrl+C다. 추가 웹 프레임워크나 외부 CDN, 인터넷 연결은 필요하지 않다. Python 의존성은 기존 `environment.yml`을 사용한다.

기본 예측은 원본 마지막 7일인 2021-09-08~2021-09-14이며, 학습 마감은 2021-09-08 00시다. 전체 기간에 같은 모델과 같은 입력 마감을 적용한다. 둘째 날 이후 실제 전력을 중간에 읽어 넣지 않는다. 이 7일 시연을 기존 D-1 검증 성능으로 설명하지 않는다.

```bash
python run_dashboard.py --build-only
python run_dashboard.py --rebuild --build-only
python run_dashboard.py --start 20210908 --end 20210914 --threshold 190
python run_dashboard.py --no-plan
```

시작·종료일은 함께 지정한다. 실제 미래 구간에는 그 날짜의 하루 24행 계획·기상 입력을 기존 원본 형식으로 제공해야 한다. 기본 시연은 생산 실적·기상 실측을 계획·예보로 가정한다. `--no-plan`은 계획·기상 없이 달력과 과거 전력 입력만 쓰는 별도 12피처 경로이며 기본 성능을 적용하지 않는다.

## 최종 모델 구성

| 용도 | 목표 | 설정과 입력 |
|---|---|---|
| 전력 추이 | 시간 평균 L1 점 예측 | FINAL_CFG, 시드 0/1/2 평균 |
| 피크 참고 | 15분 최대 L1 점 예측 | MAX15_CFG, 시드 0/1/2 평균 |
| D10 경보·일정 목적 | 15분 최대 P90 | 기존 alarm_policy 설정, 시드 0/1/2 평균 |

세 모델 모두 h7_lag에서 당일 실측 `is_off`를 제거한 33개 입력을 사용한다. 복제 가중치 0.3은 학습 마감 전의 일별 전력 곡선으로 판정한다. 점 예측의 피크 가중치 3과 나무·학습률 설정을 유지한다. `alarm_policy.available_inputs`로 마감 이후 전력과 아직 관측하지 않은 휴무 이력을 제외한다.

기본 경보는 `pred_hi_max15 >= 학습 target_max15 Q95`다. `--threshold`로 사용자가 확인한 절대 임계값을 지정할 수 있다. 값의 단위는 원본 전력값과 같아야 한다. 계약전력·단위의 확인 자료가 없으므로 기본 Q95를 계약전력이나 공식 요금 기준으로 설명하지 않는다. 15분 컬럼 해석은 D20 A안 가정이며 P90의 포함률은 보정되지 않았다.

기존 점 예측 MAE 6.51 등은 34피처의 사후 비교 결과다. 이번 운영용 33피처 점 예측의 성능으로 인용하지 않는다. 모델 파일·입력 목록·설정·학습행 수·시드·임계 근거·원본 및 소스 해시·라이브러리 버전은 `model_manifest.json`에 저장한다. 모델·입력 정책이나 원본이 변경되면 예측 캐시를 다시 만든다.

## 일정 입력과 제약

| 열 | 뜻 |
|---|---|
| task_id, name | 고유 작업 ID와 화면에 표시할 이름 |
| original_start, duration | 기존 시작 시각과 소요 시간(정수 시간) |
| earliest_start, latest_end | 가장 이른 시작과 가장 늦은 종료(24시는 당일 끝) |
| movable | 이동 허용 여부; 고정이면 시작 시각 유지 |
| resource | 같은 설비 이름의 작업은 중복 가동 불가; 빈 값은 전용 설비 제약 없음 |
| depends_on | 완료 후 시작해야 할 선행 작업 ID 목록 |
| load | 실행 시간 동안 일정하다고 가정한 부하; 모르면 비워 둠 |

추천은 하루 안에서만 이동하며 모든 작업과 소요 시간을 유지한다. 허용 시간대 밖 이동, 고정 작업 변경, 동일 설비 중복, 선행 순서 위반, 최대 동시 작업 수 초과는 허용하지 않는다. 기존 일정부터 제약에 맞지 않으면 오류를 표시한다. 작업 시간 보존은 생산량 보존의 근사이며 실제 생산량·작업 인원·품질·공정 안전 조건은 입력 자료 없이 검증할 수 없다. 근무 가능 시간을 허용 시간대로 입력한다. 야간 인건비나 요금은 계산하지 않는다.

최대 50,000개 탐색 노드에서 결정론적 분기 탐색을 실행한다. 기존 유효 일정을 항상 후보로 유지한다. 탐색을 다 마치지 못하면 확인한 후보 중 목적값이 나빠지지 않는 일정을 반환하며 최적성을 보장하지 않는다. 개선 후보가 없으면 기존 일정을 유지한다.

## 두 가지 추천 방식

**부하 시뮬레이션**은 모든 작업 부하가 있고, 기존 작업 합계가 기존 15분 최대 점 예측·P90 전체 부하 이하인 경우 실행한다.

```text
배경 부하 = 기존 전체 예측 − 기존 일정의 작업 부하
변경 시나리오 = 배경 부하 + 추천 일정의 작업 부하
```

기존 전체 부하에 작업 부하를 단순히 더하지 않는다. 목적값은 변경 시나리오의 일 최대 P90 곡선값, 임계 초과량 합계, 이동 시간 합계 순으로 비교한다. 작업의 `부하 × 시간` 합은 보존한다. P90 곡선에 가정 부하를 이동한 결과는 변경 계획으로 재학습한 P90이나 보정 신뢰상한이 아니다. 시간 평균 부하에 작업 부하를 뺄 수 없는 경우에는 시간 평균 시뮬레이션을 표시하지 않고 15분 최대만 비교한다.

**경보 회피 추천**은 작업 부하가 없거나 기존 합계가 전체 예측과 맞지 않는 경우 사용한다. 고정된 P90·임계값에서 경보 시간에 노출되는 작업 시간과 초과 비율을 줄이는 후보를 찾는다. 변경 후 전력·피크 저감량은 산출하지 않는다. 부하가 과도하면 조용히 값을 잘라 쓰지 않고 안내한다.

기본 예시 작업 A/B/C/D와 부하는 화면 사용법을 보여 주기 위한 가정이다. 실제 설비로 추출한 값이 아니다. 저감 수치는 실측·인과 효과·계약전력 초과 감소·요금 절감액을 입증하지 않는다.

## 화면 사용과 파일

1. 날짜를 선택해 예측 곡선과 경보 시간을 확인한다.
2. 예시 작업을 실제 작업의 시간·제약·부하로 수정하거나 작업을 추가한다.
3. 일정 추천을 실행해 기존/추천 시간표와 변경 사유를 확인한다.
4. 가정 부하가 있는 경우 시뮬레이션 전후 곡선을 비교한다. 부하가 없는 경우 경보 시간 작업 노출을 비교한다.
5. 예측과 일정 CSV를 내려받는다.

예측 CSV를 화면에 불러와 다른 날짜도 추천할 수 있다. 필수 값은 날짜, `hour`, `pred`, `pred_max15`, `pred_hi_max15`, `alarm_threshold`다. 한 날짜에 0~23시가 한 번씩 있어야 하며 숫자는 유한한 0 이상, 임계는 양수여야 한다. 업로드한 값은 새 모델을 학습한 결과가 아니라 제공된 예측으로 표시한다. 파일을 서버나 원본 데이터에 저장하지 않는다.

`outputs/final_app/` 산출물:

- `forecast.csv`, `forecast.json`: 시간별 예측과 D10 경보, 화면 입력.
- `model_manifest.json`, `models/*.txt`: 학습 설정과 9개 LightGBM 모델. 모델 텍스트는 Git에서 제외하며 `--rebuild`로 재생성한다.
- `demo_tasks.json`: 시연용 작업과 가정 부하.
- `schedule.json`, `schedule.csv`, `schedule_hourly.csv`: 예시 추천과 시간별 비교.
- `index.html`: 예측·예시 추천을 담은 오프라인 HTML. 편집 후 재계산은 로컬 서버에서 실행한다.

`run_all.py`의 22번째 단계도 이 산출물을 생성하고 종료한다. 과거 분석·성능 그림을 모두 다시 만들 필요 없이 `run_dashboard.py`만 실행할 수 있다.

## 수행한 검증

단위·통합 테스트 46개가 통과했다. 미래 전력 삭제·변경에 대한 세 모델의 학습 가중치·예측 불변성, 원 설정 보존, 9개 저장 모델의 재로딩, 일정 제약·부하 보존, 예측 캐시 갱신, HTTP 오류 처리를 확인했다. 실제 학습 모델의 168행에서도 마감 이후 전력을 삭제하거나 10000으로 바꾸어 입력·가중치·임계·경보가 같음을 확인했다. CSV를 재로딩한 예측의 차이는 5.7e-14 이하였다. 이 시연 조건의 점검 기록은 `outputs/final_app_validation_20261005.json`에 저장했다.

Chrome에서 날짜 변경·작업 수정·추천 실행·부하 없는 경보 회피·제약 오류 표시·CSV 다운로드·재업로드·오프라인 결과 보기를 확인했다. 계산 중 날짜를 바꾸면 이전 응답을 버리며, 모바일 390px 화면에서 표 내부 가로 스크롤을 유지한다. 이 기능 검증은 실제 공장의 생산 가능성이나 실측 저감 효과 검증과 구분한다.
